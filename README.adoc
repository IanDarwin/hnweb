= hnweb - Club Membership List

Tracks members for a small non-profit club.

Full version originally built for Orangeville, Ontario "Headwaters Nature" Club.

This shows some basic functionality of JakartaEE-Persistence in a JSF environment.

== DB Design Issues

One thing to beware of is that there is both a "Role" membership and an executive "position".
The former is the traditional EE security role, established in the MemberRole class (member_roles table).
The latter is club-specific, and controlled by the "position" field in the Member table.

Also, in the `Member` table, there is both a `type` field, which is either `Member` or `MemberArchived`
(treat as invisible to the two concrete subclasses in the table),
and a `MemberType` column, which is e.g., Family, Secondary, MailOnly, etc.

One of the issues is how to handle family memberships. In our club, some of the families are
sufficiently internet-savvy that they have 2, 3 or 4 email accounts (two parents, one or two kids)
whereas some have one for both or all people in the family.
The way I have handled families is to arbitrarily designate one
as the "family master" and all the others as "secondaries" - in JPA/Hibernate terms, a one-to-many
from Member to Member. Payments are attributed to the master member.

A few older entries weren't done this way, but the ones with "+" have been fixed 
by running `scripts/splitnames.awk`; there are still a few with "and" and "&"
that should be fixed. Be careful with splitnames, and back up the database first!

== Deploying this for your own club

This is nowhere near user-friendly, but if you know your way around
Java Enterprise servers, this will get you going.

Note that in all editing operations, you *must* use a "plain text" editor 
like vi, nano, notepad, and so on, but *not* a word processor!.

. Copy config-sample.properties to config.properties. Edit the new file 
changing the name in the orgName property
from 'Sample Club' to your organization's name (keep it short).
Ditto for the email server config in the same file.
. Set up a JTA datasource in your app server
. Change persistence.xml from the in-memory H2 to the JTA datasource you just created
. XXX That doesn't create the tables; document how to run once with the create option.
. Setup the deployment as needed (e.g., edit jboss-deployment.xml)
. Container-managed security is already configured. Just create a user in the role of club_exec in your app server.
. Deploy (e.g., mvn wildfly:deploy if you use JBoss WildFly).
. Enjoy!
